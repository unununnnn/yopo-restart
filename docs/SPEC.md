- 版本：draft-1，2026-11-09（San_Juan，UTC-3）。状态：**待 frank 批准**，未发布到 issue tracker（本次只读，不开 issue）。
- 对应诊断：`/workspace/yopo-respec/diagnosis.md`（方向 A 为主线，方向 C 为执行规则，方向 D 为发布包装）。
- 术语沿用仓库 GLOSSARY：候选、本机批准、计划、回退分支、终端占用、占用集合、预留、提案窗口、切换时刻、任务进度、虚拟中心、槽位、变阵、Oracle 暂停、安全证据、落后超界、候选漏斗。
- 新术语：**L0**（box 上 ROS-free、锁步、确定性的轻量仿真层）、**L1**（现有 PX4 SITL + Gazebo 保真层）、**上游等价策略**（按 YOPO-MINCO 上游规则选候选和处理无解）、**影子盾**（现有安全证明链以只记录、不拦截的方式运行）、**场景卡**（场景几何 + seed + 机数 + 任务 + 判据的一份声明）。

## Problem Statement

frank 想要的是：冻结权重的 YOPO 在原生 ROS 2 软件仿真里做去中心多机编队（保持、避障、变阵），3 机打通、6 机验收。项目开工 16 天，离线核心（G0/G1/G3）两天就做完了，但单机绕一根柱子飞 5 m（G2/#14）一次都没成功过。每验证一个想法要经过 Codex 多轮审查、三个 bot 接力、frank 审批和 1–2 小时的 PX4 闭环仿真，而闭环失败的主因是项目自己加的安全证明门让简单场景无解。结果是 800+ 次提交、25 个僵尸 draft、main 冻结 13 天，frank 看不到一架会飞的飞机，也算不出什么时候能看到编队。

## Solution

把「看见闭环」和「证明安全」拆开，先让飞机飞起来，再用数据决定哪些安全门值得拦截：

1. 在 box 上建 L0：几何场景、光线投射深度、真值里程计、简单动力学跟踪批准计划、锁步时钟，一次单机实验在一分钟内跑完，同 seed 结果逐位一致。
2. 规划器多一个**策略开关**：`upstream`（上游等价）和 `certified`（现行门）。L0 默认 `upstream`。
3. 现行安全证明链（ENV 证明、STOP_SELECT、计划契约复验、oracle 跟踪/落后判据）在 L0 以**影子盾**运行：每个 tick 记录「本来会不会拒、为什么」，不改变动作。
4. 用**场景卡 + 一条命令**批跑，输出结果表（成功率、最小间距、碰撞、拒绝率、墙钟）和可重放日志、短视频。
5. 按「单机 G2 → 三机编队保持 → 三机交叉避障 → 一种变阵 → 六机 + 丢包乱序」推进，每级在 L0 达标后在 L1 抽检一次，不在每次改动时跑 L1。
6. ROS 2 封装（Q5）放在同一个核心接缝上：每机一个 ROS 2 节点，L0 场景经话题驱动，验收 G4 以上时用 ROS 2 形态跑。

frank 看到的变化：每个里程碑是一条命令 + 一张表 + 一段视频；决策点集中成少数几次（见「需要 frank 拍板」）。

## Implementation Decisions

**测试接缝（只设一个）**：场景卡 → 运行器 → 结果。运行器输入一张场景卡和一组运行配置（策略、影子盾开关、动力学模型、seed 列表、层级 L0/L1），输出每次运行的结果记录和逐 tick 日志。所有票都通过这个接缝验收。若 frank 认为接缝应再往下（例如 Observation → 计划），在开工前提出。

**模块**
- **L0 世界**：场景由轴对齐盒子和竖直圆柱组成（覆盖现有 G2 场景：墙、顶、一根柱子；以及柱林、窄廊、开阔区）。G2 场景直接从现有场景 JSON 读取，保证几何一致。
- **L0 传感器**：按相机内外参做光线投射，输出深度图；量程、视场、分辨率、噪声、帧率可配；时间戳由仿真时钟给。
- **L0 动力学**：接口为「给定当前状态和批准计划，推进 dt」。首版点质量 + 一阶加速度滞后；SO3 版本后加。跟踪对象是本机批准的计划（与 L1 送 TrajectorySetpoint 的语义一致）。
- **L0 时钟**：锁步。每 tick 依次：传感器 → 规划（墙钟不计入仿真时间）→ 动力学。规划预算、帧龄、有效期一律按仿真时间判定。
- **规划策略开关**：在现有规划器入口加策略参数。
  - `upstream`：候选按网络预测走廊过滤（阈值沿用上游 0.05 m），取最高分；无可行候选时悬停当帧、下一帧照常重规划；到达判据沿用 G2 oracle 的 0.4 m / 0.2 m/s / 1 s 保持（比上游的 5 m 严，保留项目口径）。
  - `certified`：现行全部门，行为不变。
- **影子盾**：在 `upstream` 策略下，对每个 tick 被选中的候选，额外调用现有安全证据、STOP_SELECT、计划契约复验，记录「会拒 / 不会拒」和拒绝码；oracle 的跟踪界和落后界同样以记录模式运行。影子盾不得改变任何动作。
- **碰撞真值判据**：用场景几何和配置机体半径（沿用 0.35 m）对真值位置判碰撞；与 L1 oracle 判碰撞口径一致。碰撞始终是硬失败，不走影子。
- **多机**：每机一个独立规划实例和独立传感器；机间消息只走 L0 消息总线（无共享内存捷径），总线支持延迟、丢失、重复、乱序注入，参数取自 G3 离散事件测试的故障模型。协议层直接用现有轮转提案窗口和预留实现。
- **结果与日志**：结果记录含 commit、场景卡哈希、seed、层级、策略、影子盾开关、成功/失败码、到达时间、最小障碍距离、最小机间距离、影子拒绝率与原因分布、墙钟、仿真时长。逐 tick 日志可被现有重放工具读取或有等价重放命令。
- **可视化**：从日志离线渲染俯视 + 侧视视频，≤60 s。
- **ROS 2 封装**：每机一个 ROS 2 节点，内部调用同一规划入口；L0 世界作为一个 ROS 2 节点发布深度和状态、订阅批准计划；use_sim_time 由 L0 时钟提供。ROS 2 形态只在 G4 及以上验收时要求。
- **L1 抽检**：现有 PX4 SITL 栈加载同一张场景卡（仅支持 L1 已能表达的几何），可选 upstream 策略 + 影子盾；安全清单数值与 PX4 参数不动。
- **nightly**：GitHub Actions 账单问题解决前，用 box 定时任务每晚跑场景套件，结果表写到固定目录；Actions 恢复后同一命令接入 CI。
- **安全清单**：所有清单数值不改。L0 默认 `upstream` + 影子盾本身是一个需要 frank 批准的决策（作用范围仅 L0 和显式选择的 L1 抽检）。

**里程碑（每个都是「一条命令 + 一张表 + 一段视频」）**
- **M0 单机 G2（L0）**：G2 同几何场景，10 个 seed，结果表 + 影子盾拒绝率表 + 视频。
- **M1 三机编队保持（L0）**：开阔区直线 + 转弯任务，按虚拟中心 + 槽位保持。
- **M2 三机交叉避障（L0）**：柱林场景，三机穿越。
- **M3 一种变阵（L0）+ L1 抽检**：一种切换对；同时在 L1 上跑 M0 场景卡一次，出 L0/L1 对照。之后决定是否启动方向 B。
- **M4 六机 + 故障注入（L0，ROS 2 形态）**：六机，丢包/重复/乱序注入。
- **M5 交付包**：README 一键命令、结果总表、视频、已知限制（G7 口径）。

**判据建议值（待 frank 冻结，冻结前只报数不判过）**
- M0：10 个 seed 中达终点数、碰撞数（必须 0）、每次墙钟。
- M1/M2：队形误差（相对槽位）p95、最小机间距离、最小障碍距离、碰撞数（必须 0）、到达率。
- M4：同上 + 各故障注入档位下的到达率。

## Testing Decisions

- 好测试只验外部行为：给场景卡和 seed，断言结果记录里的到达、碰撞、距离、拒绝码；不测内部函数调用顺序。
- 确定性：同 commit、同场景卡、同 seed，两次运行结果记录逐字段一致（墙钟字段除外）。每张票都要带这一条。
- 真值隔离：测试断言规划器输入里没有场景几何（可用把场景几何替换成另一份后规划输入不变来验证）。
- 影子盾不干预：同 seed 下影子盾开/关，动作序列逐位一致。
- 策略开关不回归：`certified` 策略在现有离线测试和金样上结果不变。
- 故障注入：多机票必须带至少一个丢包和一个乱序用例。
- 现有可参考的测试：core 里的规划器、计划契约、冲突检查、协议节点/真实占用协议测试，以及 G2 的逐位重放测试。
- 测试只用 box CPU；`slow` 标记保留给六机和大 seed 批量。
- L1 抽检不进每次测试，只在 M3 和 M4 各跑一次，结果入表。

## Out of Scope

- 改 YOPO 网络结构或权重、训练、微调（Q4；Y6/Y8 冻结）。
- 改任何安全清单数值或 PX4 参数。
- 实飞。
- 在 L0 里做渲染级相机仿真（纹理、光照），或自研通用渲染器。
- 方向 B（PX4 锁步多实例）在 M3 之前不做。
- TRT 后端、CUDA 传感器仿真、多机 MINCO TRT 进程（Y2/Y7/Y9）在 M4 之前不做。
- 现有 #53 栈的继续修补；它冻结为 L1 现状，只在 L1 抽检需要时修最小问题。
