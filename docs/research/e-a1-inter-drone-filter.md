# 票 E-A1：机间过滤开关，默认关

只在 L0 上游候选的打分阶段加一项机间距离。默认关。关掉时，已有场景卡同 seed 的结果记录与打开这项之前逐字节相同（墙钟和 `commit` 除外）。不改冻结门，不改 `scenes/suite.txt`，不改 README，不改 `docs/tickets.md`。

E-C2 的三机开阔对向在 `upstream` 和 `hover` 上都机间相撞，最小中心距 0.631 m，而且 goto 的 `Observation` 里没有他机。对照文档把这件事写成这张票的开工条件。本票因此开工。评测只报数。

## 结论

对向卡把开关打开、阈值取机间碰撞线 0.70 m、惩罚权重取 0 之后，种子 0–9 从 0/30 到达、10/10 种子机间相撞，变成 30/30 到达、碰撞 0。最小机间从 0.631 m 抬到 0.811 m。没有死锁，也没有一次「可行集被滤空」。

六机开阔编队不走 YOPO 候选打分，卡上打开开关后轨迹与关闭相同。三机中等林走打分，但这 10 个种子里没有一条候选靠近邻机到 0.70 m 以内，过滤次数是 0，轨迹也与关闭相同。

## 打分项

开关在 `policy_params.upstream.inter_drone_filter`，缺省 `false`。打开时场景卡还要写两项：

| 字段 | 含义 |
|---|---|
| `inter_drone_threshold_m` | 同时刻中心距的阈值，必须为正 |
| `inter_drone_penalty` | 惩罚权重，必须 ≥ 0 |

走廊准入和 `safe_radius` 不动，默认仍是 0.05 m。准入之后才看邻机。距离是候选采样和邻机已提交采样在同一时刻的中心距，不外推到采样时段外面。采样步长 0.02 s，从当前时刻起 4 s。

- 权重为 0：中心距 `<` 阈值的候选离开可行集。
- 权重大于 0：这些候选仍留下，上游分数减去 `权重 × (阈值 − d) / 阈值`。
- 没人进入阈值：不改顺序，第一名仍是原来的 `select_action`。
- 有人进入阈值：可行集上的第一名仍是 argmax，同分取索引较小的那个。
- 可行集空：不新做几何回退。返回值与走廊里一个候选都没有时相同，规划码 `CORRIDOR_EMPTY_HOVER`。

邻机采样从哪来：

- goto（对向卡走这条）：开关打开时，已有的 `peer_plan` 载荷多带一份本机刚提交轨迹的采样。关的时候载荷与以前相同，不增加消息条数。
- 穿林：读总线上已经送达的最后一份已提交运动段，在打分时采样。不读更早的计划和预留，避免把替换掉的刹车停点再算进去。不改 ACK / COMMIT，也不改净空门。
- 编队：提案不是 YOPO 候选。本票不改那一层。

对照文档里的 E-A1 写的是椭球距离。论文没有给椭球系数，椭球惩罚归 E-B3。这里用场景卡上的阈值做中心距，避免和后段抢同一套公式。

## 可行集空的时候

这 30 次「打开」里，对向 10 次、中等林 10 次的 `empty_fallbacks` 都是 0。没有走到下面这条。

若过滤之后一个可行候选都不剩，调用方沿用走廊为空时的旧路径，不另造一条绕开邻机的曲线：

- goto：`hold_traj` 停在当前位置，规划码 `CORRIDOR_EMPTY_HOVER`，下一拍照常重规划。
- 穿林：`_yopo_options` 返回 `([], "CORRIDOR_EMPTY_HOVER")`。原有调用方会记一次无解，然后尝试已有的刹车多项式；刹车也交不出去就继续飞上一份已提交计划。

结果里只有开关打开才出现 `inter_drone_filter`。字段包括阈值、权重、滤掉的条数、减分的条数、`empty_fallbacks` 和 `fallback = CORRIDOR_EMPTY_HOVER`。关的时候这个字段不出现。

seed 0 上另外看过一次权重不为 0 的减分，没有进上表。阈值 1.00 m、权重 5：3/3 到达，最小机间 0.753 m，减分 601 条，过滤 0 条，可行集空 0 次。同一阈值、权重 0：最小机间 1.106 m。减分会把靠近邻机的候选留在集合里，这次它仍然到达，但贴得更近。10 种子的表用的是权重 0。

## 关掉时的逐字节比较

`tests/test_l0_inter_drone.py` 用改打分之前生成的哈希，对每张已有场景卡做 seed 0、仿真 0.5 s 的比较。去掉 `wall_time_s`、`plan_wall_ms` 和 `commit` 之后，结果记录和全部 tick 的 sha256 与改前一致。其中 `open-3drone.json` 既按套件里的 `hover` 比，也按 `upstream` 比。显式写上 `inter_drone_filter: false` 时，除场景卡哈希外，与不写这个键的飞行记录相同。

## 没做的事

- 没有把对向卡写进 `scenes/suite.txt`，没有给它加 `criteria.frozen` 或 gates。
- 没有改六机开阔和三机中等林卡上已有的 gates。这两张卡打开开关后的到达、碰撞和机间距离与关闭相同，原有的门在这组数上仍然成立。
- 没有改提交层，也没有加 D1 那种几何回退。
- 没有加 B 样条后段。
- 穿林的 Delay Check 仍是原来的值。
- `safe_radius` 默认仍是 0.05 m。

## 还没解决的

1. goto 每拍只飞打分后的第一名。穿林在这之后仍会按新顺序最多试 6 条，冲突则走原来的提交检查。对向卡这 10 个种子第一名就够了，别的几何没有测。
2. 第一拍规划时，邻机的采样还没送达。对向卡靠后面的重规划拉开。若两条轨迹在第一次重规划之前已经交叠到 0.70 m 以内，这项来不及起作用。
3. 阈值等于碰撞线。点质量跟踪仍可能把中心距再吃掉一截。这 10 个种子打开后最紧是 0.811 m，不能当成别的卡也有同样余量。
4. 权重大于 0 的减分只在对向卡 seed 0 上探过，没有 10 种子的表。
5. 六机开阔的机间间隔仍由编队预留决定。要把候选打分用到编队上，得先让编队产生 YOPO 候选。那不是这张票。
6. ROS 2 编解码的 `peer_plan` 只保留 `code`。开关打开时，采样留在进程内总线里，过不了话题。这次评测是进程内、零故障。丢包后邻机只能用上一份已经送达的采样，没有单独跑故障档。
7. 中等林的失败模式仍然是树，不是邻机。过滤次数为 0，和对照文档里「方案 A 消不掉撞树」一致。
8. 对向卡不在本 PR 里。重跑要先从 E-C2 的分支取出哈希为 `28c41923662d93a33a5d707bc717fc8070c9c6f8020d66be60de842ced659d6e` 的那张卡。

## 怎么重跑

对向卡从 E-C2 取出后，打开开关只加三行，其余字段不动。六机和中等林同样处理。种子 0–9，影子盾可以关掉。下面用对向卡做例子。几何文件要和场景卡放在同一目录。

```bash
git rev-parse HEAD
git show origin/ec2-swap-3:scenes/swap-3-open.json > /tmp/swap-3-open.json
# 在副本里加上 policy_params.upstream：
#   inter_drone_filter: true
#   inter_drone_threshold_m: 0.70
#   inter_drone_penalty: 0
.venv/bin/python -m yopo_l0.run --scene /tmp/swap-3-open.json --seed 0 --no-shadow --out /tmp/ea1-off
```

同 seed 再跑，除墙钟外的到达、碰撞、最小机间和 `inter_drone_filter` 计数不该变。`commit` 随 HEAD 变。
