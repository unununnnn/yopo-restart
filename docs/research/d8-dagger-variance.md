不改 `core/`、`scenes/`、判据、`StudentPolicy.DEFAULTS`。官方 `/workspace/yopo-teacher-data/d6b/train/student.pt` 前后的 sha256 都是 `e4bd2116…`。只读 D7 的数据（`/workspace/yopo-teacher-data/d7`），没有开全量 D6b。数字在 [d8-dagger-variance-runs.json](d8-dagger-variance-runs.json)。

## 1. 结论

1. **D7 的起伏大部分是训练种子噪声。** 同一份数据，只换训练种子（0、1、2），同一格的到达就能从 0/30 跳到 20/30。开阔三机 r2 数据的 3 个种子合计 40 / 20 / 10（满分 60），r3 数据合计 10 / 30 / 0。D7 的「r2 40/60 → r3 10/60」落在这个极差里，分不出 r3 比 r2 差。
2. **D7 的「r0 g2 8/10」是幸运种子。** r0 基础数据换种子 1、2 重训，g2 都是 0/10（3 个种子合计 8/30）。所以 g2 在 DAgger 之前并不稳定地好，「退化」大部分不是 DAgger 造成的。留下的一点信号：r2 数据 3 个种子 g2 全是 0/30，比 r0 的 8/30 少，方向一致但只有 3 个样本。
3. **到达判定单查：既不是抖，也不是漂，是晚到。** r2 学生（种子 0）开阔场没判到达的总是 uav2。它在 5.4 s 才进入 1.5 m 的到达半径，开始 2.0 s 的五次刹停；6.51 s（1.5 m 高度是 6.32 s）进入 0.4 m 容差；7.23 s（7.11 s）速度降到 0.2 m/s 以下。之后一直满足条件，不再跳出（中断 0 次，最大速度约 0.11 m/s），误差稳定在 0.023 m。到 8.0 s 只保持了 0.77 s（0.89 s），差 0.23 s（0.11 s）。判据没改。
4. **g2 归因：三个假设里只有③（限速）有配对正证据。②（加权）方向向好但在噪声内。①（精确几何）没有证据。**
   - ① 教师侧精确几何：把 g2 的 92 个重标注作业原样重跑教师，柱子发方柱，墙也发。两版教师在 1.6 s 内的水平轨迹差中位数 0.095 m（p90 0.279 m，最大 0.883 m）。重训 3 个种子，g2 仍是 0/30（对照 r3 是 5/30）。不支持「圆柱近似和缺墙导致退化」。
   - ② g2 重标注窗加权 ×4：g2 10/30（对照 5/30），开阔 110/180（对照 40/180）。种子 2 是本票唯一一个开阔 60/60 且 g2 10/10 的检查点。但另两个种子 g2 都是 0，和 r3 的 0 / 5 / 0 在 3 个种子的极差内，算不上确认。
   - ③ 结点水平速度上限 2.0 m/s（教师 EGO-Swarm 的 max_vel）：同一组 r3 权重开关对照，是配对比较，没有训练噪声。g2 从 5/30 到 15/30，3 个种子各自是 0→5、5→10、0→0，没有一个变差。开阔从 40/180 到 70/180，3 个种子各自是 10→30、30→40、0→0。前 2 s 最大速度中位数从 2.97–3.35 m/s 降到 2.32–2.35 m/s（上限截的是结点，实际速度会超过 2.0）。但速度不是唯一原因：r2 种子 2 前 2 s 只有 0.86 m/s，照样在 4.3 s 撞柱；r0 种子 1、2 只有 1.93 m/s，也撞了。
5. **按训练种子挑检查点：挑出来的就是评估最好的那个，但这不是独立检验。** r2 挑中种子 0（评估开阔 40/60、g2 0/10），r3 挑中种子 1（开阔 30/60、g2 5/10）。L0 的种子几乎不改变轨迹，训练种子上的排名和评估种子完全一样，所以这个臂只说明挑选规则可用，不能当作泛化证据。
6. 机间碰撞：只有精确几何臂种子 0 出现，开阔两个高度各 10/10 场，都是 uav0–uav2 在 3.48 s 相撞。其他臂全部是 0。

## 2. 做法

- 数据：完全复用 D7。基础训练 3015 窗、留出 1126 窗（基础 2 场），加 D7 r1–r3 的重标注窗。「r2 数据」= 基础 + r1 + r2，「r3 数据」= 基础 + r1 + r2 + r3，和 D7 的 r2、r3 训练集逐文件相同。
- 训练：D5b r4 FitConfig，只改 `seed`，取 0 / 1 / 2，每个从头训。种子 0 和 D7 逐位同训：r2 留出水平 RMSE 0.09546074574906935，与 D7 相同；评估结果也与 D7 相同。权重 sha 因 meta 不同而不同。
- 评估：口径同 D7。开阔三机 seeds 0–9，g2 seeds 0–4，1.0 m 与 1.5 m；影子盾开，track_clearance 关，r4 接口。
- 挑检查点：候选是 r2、r3 数据各 3 个种子，在训练种子上闭环（开阔 10–18、g2 5–10，两个高度，30 场）。分数依次比较：到达架数多、碰撞少、终点误差中位数小。挑的时候不读评估种子的结果。挑选种子和评估种子不重叠，有单测锁定。
- ① 精确几何：D7 三轮 g2 作业（r1 60、r2 20、r3 12，共 92 个），学生状态不变，教师侧不发外接圆柱，改发场景卡 `g2-scene.json` 里的全部盒子：方柱、左右墙、端墙、后墙、顶板，0.1 m 实心栅格，约 9.8 万点；D7 是 2349 点。容器是 `ego-teacher-d8-{0,1,2}`。转窗口时的 L0 过滤和 D7 相同，得到 1186 / 426 / 238 窗（D7 圆柱版是 1159 / 391 / 269）。只替换 r3 数据里的 g2 重标注窗，开阔窗不动。
- ② g2 加权：r3 数据不变，D7 的 g2 重标注窗（1819 窗）损失权重乘 4，基础窗和开阔窗都是 1。
- ③ 限速：r3 数据的 3 个权重原样不动，只在评估时打开 `knot_speed_cap_mps = 2.0`。r4 接口的结点速度来自位置差分，所以逐结点把水平位移截到 2.0 m/s × 0.1 s，再截结点速度的水平分量。
- 到达单查：用 r2 种子 0 的权重，开阔 seeds 0–9、两个高度，逐架按 runner 的口径重算：100 Hz、距目标 ≤ 0.4 m 且三维速度 ≤ 0.2 m/s，连续 1.0 s。runs.json 里保留了 seed 0 两个高度上没到达那一架 4.0 s 以后的 10 Hz 速度和误差曲线。

读法：

- 误差在 7.1 s 有约 3 cm 的过冲（最小 0.007 m），之后稳定在 0.023 m 附近，没有越走越远。不是慢慢漂移。

## 6. 下一步建议

- 判据和场次时长不动的前提下，开阔场的超时有一部分是机制上的「晚到」，不是策略坏了。值得单独报「3 架都停在 0.05 m 内」的场数，和到达率并列。
- 限速是唯一有配对正证据的改动，可以作为下一票的默认对照臂。上限扫 1.5 / 2.0 / 2.5 m/s，并在训练时也约束（例如给速度标签截断，或在损失里罚超速），看能不能去掉对评估时截断的依赖。
- g2 加权要多种子（≥ 5）才能下结论。权重至少扫 ×2 / ×4 / ×8。
- 精确几何不必再投入。
- 噪声这么大，任何闭环比较都应该至少 3 个训练种子、报均值和极差，并优先用配对设计（同一权重、只开关一个评估时开关）。
- 精确几何臂种子 0 出现了机间碰撞（uav0–uav2，3.48 s），说明训练噪声也会打到机间安全上，需要一个单独的机间安全回归。

## 8. 局限

- 每臂只有 3 个训练种子，每个格子实际上只有 3 个有效样本。②和种子之间的差别都没有显著性。
