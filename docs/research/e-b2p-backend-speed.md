# E-B2p：B 样条后段提速

#55 密度场 L0 里，E-B2 后段每次调用都被 0.02 s 墙钟预算截断，0.42 档迭代次数掉到 0。本票先剖析单次调用，再在不改代价、不改默认关的前提下把同样输入跑完或跑得更远。关掉时不进求解器，全仓结果应逐位相同。

剖析和提速前后的合成轨迹计时用 `scripts/e-b2p-profile.py`。对照闭环用已有的 `scripts/e-combo-a1-d1-b2.py`、`scripts/e-combo-six-forest.py` 小批量（combo 臂、seed 0）。墙钟不参与轨迹；预算命中按 `budget_cut` / `backend_budget_cuts`。

## 剖析

对一条长约 2 s 的穿场匀速直线，在 main `026cad2` 的原求解器上拆阶段（盒上 1 分钟 loadavg 当时是 0.48，单进程，重复 7 次）。cProfile 把时间集中在 `_sdf_cylinder`：每个障碍一次 Python 循环，密度场 56 / 112 / 168 根柱子，每次代价求值和每次净空检查都扫全图。其次是 `_kin_ok` 里 core 的 Bernstein 二分（`numpy.polynomial` 开销大），一次约 10–13 ms，发生在求解之后，不计入截断，但抬高了上报的 `time_ms`。

## 改了什么

只动 `yopo_l0/backend/`。代价公式、权重、铰链门槛、L-BFGS 的 `ftol` / `gtol` / `maxls` / `maxcor` / 迭代上限都不变。开关和限额仍在 `config.py`，默认关。

1. **障碍打包 + 向量化 SDF。** 一次调用把圆柱 / 盒子 / 地面收成数组。直立圆柱走二维径向公式，斜柱和盒子批量算。每个点只给最近的那一个障碍求梯度。
2. **AABB 宽相。** 铰链只留下界距离小于 `d_safe` 的障碍，与「只罚侵入门槛」等价。求全局最小净空时先用 2 m 宽相，若有的采样点还没有半径内的见证，再扩到全图，不漏最近障碍。
3. **代价向量化，布局预计算。** 三阶差分、速度 / 加速度铰链用滑窗和 `einsum`。`_sample_layout` 按段数缓存。`_fit_free` 和净空检查用 Horner 批量求轨迹点，不再逐点 `evaluate`。
4. **三次段运动学解析判定。** 后段产出的是三次段：加速度在端点取范数最大，急动度是常向量，速度的驻点来自 `v·a = 0`（三次方程）。口径与 `check_derivative_bound` 相同：必须严格低于 `limit - 1e-9` 才算 SAFE。证不出或不三次时仍退回 core。
5. **求解器走 `fmin_l_bfgs_b`。** `scipy.optimize.minimize(..., method="L-BFGS-B")` 的包装在这台机器上能单独吃掉十几毫秒，几乎就是整份预算。底层 `fmin_l_bfgs_b` 用同一组 `factr`（对应 `ftol=1e-12`）、`pgtol=1e-6`、`maxls=16`、`m=8`，在放开预算、跑满 8 次迭代时，控制点与 `minimize` 逐位相同。预算截断、记录最优可行点的逻辑不变。

数值核对（随机点、密度场 / 密林 / 六机疏林 / g2）：打包最近距离和梯度与逐障碍循环最多差几个 ulp；批量求值与 `evaluate` 逐位相同；解析运动学与官方判定在 300 条随机三次段上一致；有限差分梯度仍过原测试；放开预算跑满 8 次时，优化后轨迹与旧求解器位置差为 0。

## 提速后的耗时和预算

同样的 2 s 穿场直线、同样的 0.02 s 预算。提速后的表在 1 分钟 loadavg 约 6.0 时测（盒上另有会话在跑），墙钟会被抬高。12 次重复里的最小值更接近不被抢占时的耗时；p50 含抢占。提速前那组是 loadavg 0.48 下测的，p50 和最大几乎贴在一起。

| 场景 | 提速前 p50 / p95 ms | 提速前迭代 p50 | 提速前截断 | 提速后 min / p50 / p95 ms | 提速后迭代 p50（最小–最大） | 提速后截断 |
|---|---|---|---|---|---|---|
| 密度 0.14 | 40.1 / 45.0 | 3 | 7/7 | 10.1 / 16.1 / 24.8 | 8（3–8） | 3/12 |
| 密度 0.28 | 44.0 / 45.0 | 1 | 7/7 | 15.8 / 23.9 / 30.0 | 5.5（4–8） | 10/12 |
| 密度 0.42 | 46.4 / 47.9 | 0 | 7/7 | 14.4 / 23.1 / 26.9 | 6.5（4–8） | 8/12 |
| 密林 | 39.5 / 41.4 | 3 | 7/7 | 7.4 / 16.1 / 20.6 | 8（8–8） | 0/12 |
| g2 柱子 | 13.8 / 16.5 | 0 | 0/7 | 2.3 / 2.6 / 3.0 | 0（0–0） | 0/12 |

不被抢占的切片上，三个密度档和密林都能在预算内跑完：最小耗时 7–16 ms，并能到达 8 次迭代（g2 仍因梯度已小而在 0 次停下，整次调用从约 14 ms 收到 2.3 ms）。loadavg 6 时 0.28 / 0.42 的 p50 仍会压过 20 ms，截断比例随墙钟抖动，不是求解器又回到「一次迭代都做不完」。把预算放到 1 s 时，0.42 档 8 次迭代的最小耗时 13.2 ms。

阶段本身（同样在提速后、传入已打包障碍）：0.42 档一次代价约 0.3–0.5 ms（以前 8.1 ms），净空检查约 0.4–0.6 ms（以前 9.8 ms），运动学检查约 0.5 ms（以前 11 ms）。
