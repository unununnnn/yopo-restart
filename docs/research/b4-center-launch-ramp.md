# 票 B4：交叉卡虚拟中心起步斜坡（只报数）

B3（`b3-sitl-launch-tracking.md`）的候选 (a)，即起步 1.5 s 内计划加速度上限 3 m/s²，在锁步 SITL 上最有希望，但它在 L0 冻结套件上让 `crossing-pillars` 的 seed 1、6、9 编队误差 p95 到了 6.13 / 6.29 / 6.13 m，超过冻结线 6.0 m。原因是虚拟中心从 t_go 起一步就按巡航速度 3.5 m/s 走，飞机加速被压住，必然先落在后面。本票让虚拟中心也按同一个加速度从 0 匀加速到巡航速度，再匀速走完。

只报数，判据未冻结的地方照旧只报数。开关默认关，打开时 L0 结果 `upstream_deviation=true`、带 `center_ramp_deviation`，SITL `b2_deviations` 带「偏离上游：虚拟中心起步按 3 m/s² 斜坡」。每趟 SITL `px4_parameters_written` 都是空列表。不改冻结文件，不改 `sitl_bridge.py`、`switch.py`、`formation.py`。逐趟数字在 `b4-center-launch-ramp-runs.json`。时间都是 2026-11-15 UTC-3。

## 开关

单独一个键，放在 B3 的同一组 `policy_params.b3` 里：`center_ramp_mps2`（SITL `YOPO_B2_FIX=ramp=<a>`）。不和 (a) 绑死，这样可以单开斜坡做对照；两者一起开时取同一个数 3 m/s²。缺省没有这个键，`_Rail` 与改前逐行相同，task_hash 不变；给了才进 task_hash。

斜坡开时中心线弧长：τ < t_r = v/a 时 s = ½·a·τ²，之后 s = v·(τ − t_r/2)，夹在 [0, length]。总时长多 t_r/2（3.5 m/s、3 m/s² 时 t_r = 1.17 s，多 0.58 s），起点、终点槽位不变，斜坡中心永远不超前缺省中心。中心线同时是编队误差的参考（无门控时）和规划目标的时刻表，所以两处一起变。林带卡默认进度门控，参考和时刻表都走全队投影低分位，斜坡只改 `motion_duration_s`。

## 默认值建议

**不建议「可考虑默认开」，保持默认关。** 本票的条件是 L0 冻结套件全过、SITL 不差于 (a)。第一条满足，第二条不满足：

- L0：(a)+斜坡 crossing-pillars 10/10 过冻结判据，编队误差 p95 最大 4.31 m（缺省 4.61 m，(a) 6.29 m）；三张林带卡都过。
- SITL 成功数：两批 8/10、7/10，(a) 是 8/10。锁步下差一两趟在噪声内，算持平。
- SITL 横向跟踪 p95：两批中位数 0.81、0.98 m，都比 (a) 的 0.65 m 高，也比缺省 0.72 m 高。两批方向一致，不像是单批运气。
- SITL 到达时间：第一批 10.95 s 和 (a) 的 10.49 s 接近；第二批 15.98 s 明显慢。

只开斜坡（不开 (a)）在 L0 上也全过，编队误差 p95 最大 3.86 m；它没在 SITL 上跑。

可能的原因：斜坡也改了规划目标的时刻表，起步段目标点离机头更近，YOPO 选的横向绕行更急；(a) 单独开时目标点在远处，横向余量大。这只是推测，本票没有拆开量。
