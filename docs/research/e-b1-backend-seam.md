# 后段接缝（E-B1）

后段插在「YOPO 已经选出一条多项式」和「这条多项式进入提交」之间。它不重选候选，也不改提交。

开关是场景卡 `policy_params.backend.enabled`。只有 JSON `true` 才打开。缺省、`false`、字符串都不算打开。关掉时不导入求解器，不读场景几何，不替换多项式对象，结果记录里也不出现 `backend` 字段。已有卡不写这个字段，同 seed 的轨迹与加这一层之前逐位相同。

网络权重不改。已冻卡的 `criteria.gates` 不改。`scenes/suite.txt` 不改。`ego-planner-swarm` 是 GPLv3，本仓库根目录没有 LICENSE，不复制那份源码。代价按论文里各项的角色重写，数值不是论文的 λ。

求解器在 [e-b2-bspline-prototype.md](e-b2-bspline-prototype.md)。本页只钉接缝。E-A1 的候选打分、D1 的提交层几何回退都不在这里改。

## 插在回路的哪

两条路都是：候选已经变成一条 `PiecewisePolynomial` 之后，交出去之前。

单机 goto（`UpstreamPolicy.plan`，`scenes/g2-pillar.json` 这条）：`select_action` 选出序号，`minco_two_piece` 得到多项式。后段在这之后、赋给 `plan_obj` 之前。单机没有协议 COMMIT。动力学下一拍跟踪的就是这个对象，影子盾在 `plan()` 返回之后才记录。走廊空、本帧改悬停时不调用后段。

穿林（`CrossingFleet._yopo_options`）：一次前向，`rank_candidates` 的顺序不改。第一条拟合成功的前缀（`_fit_yopo` 或超前机的 `_fit_short`）交给后段，然后才放进 `motions`。后面按分数再试的几条仍是原来的多项式，留给冲突回退。净空门、`_as_plan`、`make_plan`、预留、ACK、COMMIT 都还是原来的函数。

不改 `select_action` / `rank_candidates`。不改制动分支、计划契约和协议节点。

短于 0.6 s 的多项式原样交回。超前机那条 0.3 s 短前缀因此不动。承诺视界上的前缀（三机 1.0 s，六机被抬到 1.75 s）长于这条线，会进后段。

## 输入和输出

输入：

| 项 | 从哪来 | 本原型怎么用 |
|---|---|---|
| 选中的多项式 | 上面那一步 | 拟合的对象。首尾 PVA 从它两端读 |
| 障碍 | 场景卡里的圆柱、盒子、地面。只有开关打开才读 | 最近表面的有符号距离。没有 ESDF |
| `a_max` | 场景卡动力学，缺省 6 | 曲线加速度软上限，也是事后运动学检查的加速度上限 |
| `v_max` | 原型里写死 6，卡上可以盖 | 曲线速度的软上限。计划契约的速度上限仍是 20，不在这里收紧 |
| 目标点 | 这一拍的目标 | 签名里留着。末端 PVA 钉死在 YOPO 前缀上，不另加终端进度 |
| 邻机轨迹 | 无 | 不加。机间椭球是 E-B3 |

输出：另一条 `PiecewisePolynomial`，起点时刻相同，首尾位置、速度、加速度与输入一致（1e-6 以内），时长等于输入。优化变量是均匀三次 B 样条的中间控制点。头三个、尾三个由两端 PVA 定死，不动。

失败，或者新曲线的运动学不过、采样净空比输入还差 1 cm 以上：返回输入的那一个对象。调用方看不出失败，原来的净空、契约、COMMIT 照旧。

开关打开时，每次调用在结果的 `backend` 里汇总：调用次数、采用次数、迭代次数、墙钟 p50/p95、原因。这个块是墙钟和计数，不进冻结门。关掉时没有这个块。

## 代价

均匀三次 B 样条，节点间距大约 0.22 s，段数夹在 6 和 12 之间。

三项，都有解析梯度：

- 平滑：控制点三阶差分的平方和。直线上这项是 0。
- 碰撞：曲线采样点到最近障碍表面的有符号距离。低于 `clearance_m + 0.05` m 就加平方铰链。`clearance_m` 缺省是机体半径 0.35 m。多出来的 5 cm 是因为铰链在门槛上梯度为零。
- 可行：采样点上的速度、加速度。超过 6 就加平方铰链。罚的是曲线本身，不是控制点差分。差分是凸包上界，弯一下上界就爆，曲线的加速度还远没到 6。

权重：平滑 1，碰撞 40，可行 0.1，另外 0.15 把中间控制点锚在拟合上。论文是 λ_s = 1、λ_c = λ_w = λ_t = 0.5、λ_d = 0.1，碰撞用 `{p, v}` 平面距离。那组数不能直接套到米制铰链上，所以这里的 40 是原型自己的。没有 λ_w，没有终端进度项。

求解：`scipy.optimize` 的 L-BFGS-B。不用商业求解器。迭代上限 8。墙钟预算 0.02 s，从进入求解器算起，不含第一次导入 scipy。预算到了就停，用已经算出的最低代价的点。预算是墙钟，不推进仿真时间。

采用之前还要过两道，和提交用的是同一类检查：首尾 PVA 对得上；速度 ≤ 20、加速度 ≤ `a_max`、急动度 ≤ 20000（计划契约，不是把速度硬收成 6）。过不了就从全步长往回缩到一半、四分之一、八分之一，再不行就用拟合本身。都不行就交回 YOPO。

## 失败时

不把异常抛进规划器。数值失败记 `exception`，前缀太短记 `too_short`，运动学不过记 `kinematics`，净空变差记 `clearance`。记录只在开关打开时出现。

交回的是原来的多项式。穿林里它继续走净空门和 `make_plan`。不过契约就换下一条候选，或者刹车，规则与打开后段之前相同。单机 goto 没有这层过滤，所以后段自己先把首尾和加速度卡住，不把一条加速度爆掉的样条装进 `plan_obj`。

## 承诺视界 1.75 s、Delay Check、影子盾

后段不决定承诺多长。穿林先按 `commit_horizon_s` 把 YOPO 截成前缀，再拟合、再在末端接上用场景 `a_max` 停住的一段。后段优化的就是这条已经截好的前缀，不把它改长，也不改 `window_len_s`。

六机构造时，视界短于 `N × window_len_s + 0.25` 会被抬到下界。六机、窗口 0.25 s 时下界是 1.75 s（[ADR 0011](../adr/0011-brake-gap-horizon-and-amax.md)）。三机的下界是 1.0 s，卡上写的就是 1.0，构造时不抬。本原型的密林卡是三机，进后段的前缀是 1.0 s 那一档。1.75 s 仍是六机的构造规则，后段不另写一个视界。

Delay Check 不动。穿林 `delay_check_s` 仍是 0，收齐 ACK 当拍提交（[ADR 0012](../adr/0012-rmader-dual-track.md)）。后段不打开等待，也不把提交时刻和优化器绑在一起。

影子盾仍只记录、不改批准动作（[ADR 0007](../adr/0007-l0-default-upstream-shadow.md)）。它在计划已经选完之后看那条曲线。后段若换了多项式，盾记录的是换过的那条；它仍然不会因此放行或拦截。没有地图的时候，`ENV:UNKNOWN` 可以和飞过去同时成立（[ADR 0010](../adr/0010-certified-env-unknown-reported.md)）。拒绝率变低不算优化成功。

## 不在这张接缝里

- 机间椭球、邻机采样、`C` 和 `c`（E-B3）。
- 把 Delay Check 改成非 0。
- 重排候选或改 `safe_radius` 的默认 0.05 m（E-A1）。
- 提交层的几何回退（D1）。
- 已冻卡的到达、碰撞、距离门。
