# 票 13e 幽灵刹车停点与林带进度门控

判据未冻结 / report-only。碰撞数照实写。决定见 [ADR 0015](../adr/0015-ghost-brake-stops.md)。

基线是 main `b289b2e`（13a、13c、13d、13b 都已合入）。L0，影子盾开，`safe_radius` 0.05 m，动力学 kp 4、kd 3、tau 0.1、a_max 6。承诺视界 1.75 s，计划 a_max 6，穿林 `delay_check_s=0`，`goal_bias` elastic-slot。不改 yopo-swarm，也不改 vendored core。六机 medium / sparse，seeds 0–9。

## 修法

| 代号 | 改动 |
|---|---|
| main | `b289b2e` 原样：林带 `progress_gate=true`，分位 0（min），超前 1 m 以上就悬停 |
| A | 落后机 3 s 内进度没涨过 0.1 m、上一拍又是跳过或刹车时，移出门控的分位计算 |
| B | 林带卡 `progress_percentile=20`（六机里第二低） |
| C | 超前机连续悬停 4 个自己的窗口后，放一扇窗口走原 YOPO |
| D | A，再加上选侧向通道时把邻机到 `inf` 的停点当成球避开 |
| E | 林带卡 `progress_gate=false` |
| F | 六机林带提案前自检只看每个邻机最后两份计划（committed + previous）加预留，门控保持开 |
| G | A + F |
| **E+F** | E + F，即本票合入的改动 |

## 合计

- **官方 p95** 就是结果里的 `formation_error_p95_m`。门控开时对着门控弧长上的槽位，门控关时对着墙钟 × speed 上的槽位，两种口径不能直接比。

## 根因打点

main，medium seed 1：t ≥ 12.75 s 起，uav2 的投影进度停在 9.85 m，是全队最低，每扇窗口都 `CONFLICT_SKIP`，冲突对象只有 uav0。其余五架超前 1 m 以上，一直 `LEADER_HOVER`。之后 40 s 没有人动，uav2 本地提交 7 次，其他机 33–34 次。

在 t=14.25 s 把 uav2 自检里每份邻机计划逐一拿出来比：冲突的只有 uav0 在 6.25、7.75、9.25、10.75 s 提交、早已被替换的四份计划，它们的刹车停点在 (13.57, 2.02)，离 uav2 的 (12.85, 3.06) 约 1.2 m。uav0 当前的计划在 18.9 m，不冲突。修法 A 的 medium seed 2 更清楚：t=20 s 时 uav0 已经飞到 22 m 以后，uav2 直到 50 s 仍然只和 uav0 在 10.75–13.75 s 的旧计划冲突。sparse seed 9 是同样的形状，挡住 uav2 的是 uav0 和 uav4。

## 和 13c 文档里 53/60 的差距

[13c 结果](13c-elastic-clearance.md)里 sparse 53/60 是在 13c 分支 `c24bb0f` 上测的。那时还没叠 13a、13d：急刹按写死的 `_LIMITS a_max=80` 生成，承诺视界 1.0 s，前缀盖到 1.5 s，场景卡哈希仍是 #18 那一版。合并提交 `f23320d` 带进 13a（视界 1.75 s、a_max 6）和 13d 后，那张表没有重跑。所以 E 的 47/60 和 53/60 不是同一份代码，差距大概率来自 13a 和 13d 的合入。每一项各占多少没有分开跑，这里不下结论。
