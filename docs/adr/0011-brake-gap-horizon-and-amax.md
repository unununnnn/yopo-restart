# 承诺视界盖住一轮窗口，急刹 a_max 等于 L0 动力学

## Context

票 11c 把六机穿林里的急刹空档追到两条被放松的不变量，不在编队目标，也不在进度门控。frank 2026-11-09 按这个建议开工，本 ADR 只记下原因和因此锁死的构造期检查。

轮转窗口里，一架飞机要等满 `N_agents × window_len_s` 才再次拿到提案权。它在自己的窗口里提案，新计划的 `t_start` 是下一个窗口沿。上一条已提交计划若在这之前就结束，中间只剩终端保持：运动段已经停了，制动分支也不再覆盖这段时间。邻机冲突需要急刹时，本机没有一段还在飞、并且带着制动的承诺。这就是空档。

`commit_horizon_s` 是交出去的 YOPO 前缀第一档长度（`CrossingFleet._fit_yopo`）。三机卡 `window_len_s=0.25`、`commit_horizon_s=1.0`，下界 `3 × 0.25 + 0.25 = 1.0`，刚好盖住。六机卡沿用同一组规划参数（票 11b 把 JSON 锁成与三机相同），仍是 1.0。六机下界是 `6 × 0.25 + 0.25 = 1.75`。1.0 比一轮窗口 1.5 s 还短，前缀结束后、下一次本机 COMMIT 生效前有一段没有急刹的空档。多出来的 0.25 s 是下界里的固定余量，不是再一个窗口。

另一半在加速度。急刹走 `brake_branch`，时长从 `max(0.2, 1.5 × speed / a_max)` 起。计划契约以前写死 `a_max=80`（`v_max=20`、`j_max=20000` 只为了收下上游多项式的速度尖峰）。L0 动力学 `PointMassLag` 的 `a_max` 是 6，场景卡也是 6。巡航 3.5 m/s 时，80 的下限就是 0.2 s，6 的下限是 `1.5 × 3.5 / 6`。那条 0.2 s 的五次多项式过不了加速度 6 的契约检查：占用管子按「已经停了」保持，点质量还在滑。管子和真减速对不上的那一段，也是 11c 的急刹空档。

编队目标的混合、追赶和进度门控不在这条因果里。本 ADR 不改那些逻辑。

## Decision

- 构造 `CrossingFleet` 时强制 `commit_horizon_s ≥ N_agents × window_len_s + 0.25`。场景卡或默认值（缺省 1.0）短于下界就抬高到下界，并打一条 warning。非正数仍报错，不抬。
- 不改六机场景卡 JSON。票 11b 要求这些卡的规划参数与三机卡相同；1.0 对三机已经在下界上，抬高只发生在机数使下界变高的构造里。协议 `task_hash` 用抬高后的值。
- 急刹和计划契约的 `a_max` 等于该卡的 L0 动力学 `a_max`。卡上没写时用 `PointMassLag.a_max`（当前 6）。禁止再写死计划 `a_max=80`。`v_max` 与 `j_max` 仍是原来的 20 和 20000，本票不收紧它们。
- 前缀从长到短的拟合阶梯、目标偏置、到达保持、编队目标与进度门控都不改。

## Consequences

- 三机、窗口 0.25 s、视界 1.0 s 的卡构造时不抬高，也不打这条日志。六机同一张数字会得到视界 1.75 s，并留下日志。
- 计划契约不再接受一条动力学跟不上的 80 m/s² 急刹。过不了 `a_max=6` 的曲线仍走原来的更短前缀或刹车回退，选择规则不变。
- 编队保持和变阵的计划限幅不在本 ADR 里。它们不是 11c 这处 `a_max=80`。
